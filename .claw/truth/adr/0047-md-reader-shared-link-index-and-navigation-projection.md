# ADR 0047：文章关联与图谱共用索引，导航筛选只改变显示

## 背景

文章页需要在未打开图谱时显示出链和反链；INDEX/MOC 又会集中占据图谱中心。若关联区另扫描一份数据、或为改善图形从索引删导航边，会出现事实不一致和额外扫描。文章返回图谱还需要恢复固定选中。

## 决策

服务端 link-index 是显式链接事实的唯一来源。前端按项目/Profile 共用请求缓存，文档打开时提前加载，图谱与关联区复用。导航过滤仅在构建显示图时进行，不改 nodes/edges/backlinks 原始载荷。

图谱选中只存于按项目分桶的 graphViewStore。「回到图谱」写 selectedId 后再挂载，使用现有固定信息面板。显示选项也放在该 store；文字路径切换仅重绘。

## 备选方案

- 关联区单独请求或逐篇扫描：重复工作且易与图谱事实不同，未采用。
- 在 link-index 删除 INDEX/MOC：反链事实丢失，无法关闭过滤恢复导航，未采用。
- 新增 focusSelectedId prop 并覆盖恢复逻辑：形成两套选中来源和竞态，未采用。
- 文件监听与实时失效：本轮保留显式刷新，避免扩展到额外后台扫描。

## 后果

同一载荷可投影出不同图形，截图数量不等于全库节点数。外部内容变化仍需手动刷新；默认值与例外由 [图谱交互 Truth](../features/md-reader-graph-interaction-and-state-boundary.md) 维护，缓存及解析限制由 [链接 Truth](../features/md-reader-wiki-links-and-graph-boundary.md) 维护。实际目标被过滤隐藏时，文章返回操作需开启必要选项以确保选中可见。
