## (a) 抽链 BUG：已确认，而且有两种相反方向的错误

### 漏边：省略扩展名的 wiki 目标没有正规化

`server/link-index.mjs:29` 的 `toProjectPath()` 只拼接路径，`extractLinks()` 调用时没有补 `.md`。随后第 197 行以 `pathSet.has(link.target)` 精确匹配，失败便直接写 broken 并跳过建边。

例：主文第 46 行 `[[原型人物|原型人物]]` 得到 `writing/文字创作/黑墙之下/原型人物`；扫描表实际有 `writing/文字创作/黑墙之下/原型人物.md`。15 条真实 wiki 引用全是同样情况，逐条检查对应 `.md` 文件均存在，也在返回的 nodes 中。

渲染端 `src/markdown/remark-wiki-links.ts:40` 附近明确补 `.md`，且仅访问 AST text 节点。因此“阅读能生成正确目标、索引却判不存在”有源码证据；本次没有操作 UI 点击，不能把源码判断冒充点击实测。

影响不仅是少画线：反链表也在 `continue` 之后才生成，因此这 15 条反链同样丢失。改布局参数无效。

### 假 broken：代码示例被当成真实引用

现有索引直接对整个 Markdown 执行 `matchAll`，没有语法上下文。实际剩余四条 broken 全是 inlineCode：

| 源文件和行 | 示例 | 错误结果 |
|---|---|---|
| README.md:81 | `[标题](../小篇/钓鱼.md)` | 被记为 Markdown broken |
| README.md:82 | wiki 语法示例，含转义竖线 | 被记为 wiki broken |
| README.md:84 | `[[...]]` | 被记为 wiki broken |
| work/daily/2026-11-13-evening.md:58 | `[[1]]` | 本来在说明脚注改写，反被抽成 wiki broken |

对原源码函数做内存探针，行内代码和 fenced code block 中的 `[[Target]]` 均会返回引用，确认两者都未排除。本次真实快照四个假阳性都来自行内代码，未发现 fenced code 导致的真实库假边，不能混称已经发生。

若这些示例碰巧与真实文件同名，还会制造假边，风险不限于 broken 数字不好看。

## (b) 功能不完善：成立，但不是零边的必要解释

当前已有全局/局部图、N 跳、孤立节点开关，不能报告成“没有局部图”。`src/graph/linkGraphAdapter.ts` 只是从 index.edges 构建邻接、筛选，再交给布局；并不自动发现内容关系。

对 clone 的 src/server 检索显示：backlinks、broken、titles 已在接口及类型层提供，但没有找到它们的用户界面消费者；titles 只是标题映射，并未实现未链接提及搜索。反链的 snippet 实际只是链接 label，不是原段落。由此缺少一条完整整理流程：从目标看到引用上下文→审阅未链接提及→定位修正 broken。

“隐藏两份 INDEX，专看正文关系”也未见专门过滤入口，现有图谱选项主要是 scope/hops/includeIsolated。建议增补筛选而不是删除目录边。上述为当前 clone 的静态核对，未启动浏览器确认已部署 UI。

## (c) 内容本来没写双链：成立，决定修好后能否形成网络

71 篇中只有 5 篇写 wiki 引用，而且现存 15 条大多来自迁移后的父子页导航。黑墙人物、地图、玩法、视觉之间已有明显内容依赖，却没有显式引用。比如人物设定明确说人物折射医疗配给、AI 失业和隐形阶级；游戏设计又直接讨论 Alex 的玩法功能，仍未指回人物页。
