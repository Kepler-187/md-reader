# 双链与关系图谱

## 概述

`md-reader` 在原有「标准 Markdown 内部链接」之外，增加了两件事：

1. **双链**：识别 Obsidian 风格的 `[[目标]]` 语法，按内部链接打开目标文档。
2. **关系图谱**：力导向布局、邻接高亮、拖动弹性与节点信息面板都已实现，数据来自服务端的链接索引。

双链在渲染层独立完成 AST 改写，不依赖链接索引；图谱才依赖服务端链接索引（`server/link-index.mjs`，路由 `GET /api/projects/:id/link-index`）。

## 双链语法

| 写法 | 效果 |
| --- | --- |
| `[[docs/01_产品概览]]` | 打开 `docs/01_产品概览.md`，显示文字为「docs/01_产品概览」 |
| `[[01_产品概览\|产品概览]]` | 打开目标文档，显示文字为「产品概览」 |
| `[[05_Markdown与三模式机制#常规锁定：阅读]]` | 打开目标文档并定位到该标题 |

规则细节：

- 目标省略 `.md` / `.mdx` 扩展名时会自动补 `.md`。
- 目标带 `#小节` 时，跳转沿用现有的标题定位链路。
- 目标按当前文档所在目录解析相对路径；以 `/` 开头视为项目根。

### 代码块与行内代码不受影响

````markdown
```text
[[这段不会被解析]]
```

行内 `[[这段也不会]]` 保持原样。
````

实现方式是 **remark 插件在 AST 阶段改写文本节点**，不是对源码做正则替换。正则会把 fenced code block 和 inline code 里的 `[[...]]` 一起转掉，AST 方案只处理普通文本节点，天然规避。

改写成标准 `link` 节点后，现有的内部链接解析（内容根校验、文件树存在性校验、点击前先保存、修饰键保留浏览器原生行为）全部原样复用，没有第二套导航逻辑。

相关文件：

- `src/markdown/remark-wiki-links.ts`：插件本体
- `src/document-renderer/readonly-markdown-renderer-impl.tsx`：挂载点，`REMARK_PLUGINS` 里排在 `remarkGfm` 之后、`remarkHeadingIds` 之前

## 关系图谱

### 入口与退出

顶部栏模式切换（常规 / 分栏）右侧有一个图谱按钮。点一次把中间文档区换成图谱，再点一次回文档。

图谱不占标签页。标签页模型的前提是「一个标签对应一个文件路径」，会话恢复、拖拽排序、活动标签判断都依赖它。图谱是跳转工具，选完节点就离开，做成模式切换比塞进标签页便宜一个量级。

### 作用域

| 模式 | 含义 |
| --- | --- |
| 全局 | 所有文档及其引用关系 |
| 当前文档邻近 | 只保留当前文档 N 跳以内的节点（N = 1 / 2 / 3） |

还有一个「孤立节点」复选框。默认关闭：没有任何连线的文档不画，否则大量模板和孤立笔记会把画面撑散。

### 交互

| 操作 | 行为 |
| --- | --- |
| 空白处拖动 | 平移视口 |
| 滚轮 | 以指针为锚点缩放（0.06×–4×） |
| 拖动节点 | 节点跟随指针，相连节点弹性回弹 |
| 点击节点 | 固定选中，高亮一圈相邻节点与相关边 |
| 悬停节点 | 显示信息面板（未固定时） |
| 点空白处 | 取消固定选中 |

**点击与拖动靠位移区分**：pointerup 时位移小于 4px 判为点击，超过则判为拖动。拖动结束不会误触发选中。

### 信息面板

悬停时面板跟随指针显示；点击后固定（边框加粗、徽标显示「已固定」），鼠标移开不消失，后续悬停其它节点也不会覆盖已固定的选择。

面板内容：标题、路径、链接数、标签，以及「进入文章」按钮。

点「进入文章」退出图谱、切到常规模式的阅读态（`regularViewState: 'locked'`）并打开该文档——是读书而不是改稿。当前若是分栏模式也会切回常规，否则右侧预览会抢焦点。

### 视觉与动效

渲染从 SVG 改为 Canvas，逐项对照 `@veewo/mechanics` 的 `drawForceRaster` 迁移：

- **节点分档配色**：普通淡、次级更饱和、核心最饱和并带同色外晕（远看像地图上的城市）
- **聚焦退让**：选中节点的邻居换饱和色，无关节点退到 alpha 0.28
- **锥形缎带连线**：相关边画成源端粗深、目标端细浅的渐变带
- **流动光点**：三个点按弧长匀速从源流向目标；`prefers-reduced-motion` 时只留一个静止点
- **标签避让**：名字画在圆下方、屏幕固定字号；缩小时按连接度挑选，核心与聚焦必显；空间网格避让，不压到其它圆

配色算法（`forceNodePalette`、`FORCE_EDGE_REST`、`hexAlpha`）整段移植，没有另调色板。

### 状态跨开关保持

图谱坐标、相机（平移缩放）、固定选中、拓扑指纹按**项目分桶**保存：

- 离开图谱去读文章，再点回来：看到同一张图、同一个视口、同一个固定面板
- 切换内容库：不复用别的库的坐标与选中
- 数据变化：拓扑变了丢坐标（旧坐标对不上新图），选中节点若仍存在则保留；节点被删则清空选中

实现见 `src/graph/graphViewStore.ts`。

### 布局

力导向布局复用 `@veewo/mechanics`（`VeewoGames/mechanics`）的 `force-simulation` 与 `force-geometry`。那几个参数是在真实画布上调过的：

- alpha 每步向目标靠拢 2.28%，约 240 步冷却
- 斥力强度 2000，连线静止长度 120
- 节点按连接数分三档半径：普通 8–13px、次级枢纽 16–24px、核心枢纽 30–44px
- 核心档取前 2%（最多 24 个），次级档取前 10%（最多 150 个）

重新调一遍这些参数不划算，所以三个文件只改了 import 路径，逻辑原样保留。

**两种运行方式并存**：

- **首次进入**：`layoutGraph` 同步跑到收敛后丢弃引擎（实测 6 节点 214 帧），调用方直接拿最终坐标，不用处理中间态。
- **拖动**：`createLiveForceLayout` 保留仿真引擎并持续出帧，拖动时节点实时跟随、邻居弹性回弹。

**恢复布局时不建引擎。** 有上次的坐标就直接画——一旦建仿真并冷却，几百毫秒内会把恢复的图挤歪，「重开看到同一张图」就守不住。同理，`pointerdown` 只记录候选，不调用 `dragStart`；单纯点击也会走 `pointerdown`，那时启动仿真同样会推歪。真正越过 4px 阈值后才接管。

420 个节点以内走精确两两斥力，够快，不需要 worker。

相关文件：

| 文件 | 职责 |
| --- | --- |
| `src/graph/forceSimulation.js` | 力导向仿真（来自 mechanics，改 import） |
| `src/graph/forceGeometry.js` | 节点分档与连线几何（同上） |
| `src/graph/readGraphIntegrity.js` | 读取图自洽校验（同上） |
| `src/graph/forceAdapter.ts` | 链接索引 → 读取图 → 同步跑完 → 带坐标节点 |
| `src/graph/linkGraphAdapter.ts` | 作用域过滤后重新布局 |
| `src/graph/graphRenderer.ts` | Canvas 渲染（移植 drawForceRaster）：分档配色、锥形缎带、光点、标签避让、命中测试 |
| `src/graph/graphPalette.ts` | 节点配色算法（移植 forceNodePalette） |
| `src/graph/graphViewStore.ts` | 跨开关状态：坐标、相机、选中、拓扑指纹，按项目分桶 |
| `src/graph/GraphView.tsx` | 视图容器：交互状态机、面板、布局生命周期 |

TypeScript 侧对两个 `.js` 模块用 `any` 处理：`tsconfig.app.json` 开了 `allowJs`、关了 `checkJs`，模块形状由 `forceAdapter.ts` 的调用处保证，不额外维护 `.d.ts`。

## 链接索引

`src/workspace/local-bridge-access.ts` 已声明 `LinkIndexPayload` 并请求 `GET /api/projects/:id/link-index?profileId=…`。下列是前端预期的数据契约，不是当前仓库服务端已实现的返回值：

```jsonc
{
  "nodes": [{ "id": "INDEX.md", "path": "INDEX.md", "title": "库索引", "tags": [], "dir": "" }],
  "edges": [{ "source": "INDEX.md", "target": "docs/01_产品概览.md", "kind": "markdown" }],
  "backlinks": { "docs/01_产品概览.md": [{ "path": "INDEX.md", "title": "库索引", "kind": "markdown", "snippet": null }] },
  "broken": [{ "from": "README.md", "path": "wiki 链接", "raw": "[[wiki 链接]]", "kind": "wiki" }],
  "titles": { "库索引": ["INDEX.md"] },
  "scannedAt": "2026-11-13T…",
  "documentCount": 48
}
```

索引放在服务端而不是浏览器逐篇读取，理由如下：

1. 浏览器逐篇请求文件，1000 篇就是 1000 个 HTTP 请求；
2. 文件树扫描逻辑本来就在服务端，可直接复用；
3. 预期按 mtime 缓存，只重读变化的文件；仓库内尚无此索引缓存实现。

索引契约要求抽取双链与标准 Markdown 内部链接，排除外链（http / https / mailto 等）；抽取与缓存仍待服务端落地。

预期 `broken` 记录指向不存在文件的引用；图谱适配层会过滤悬空端点。当前仓库服务端尚不能生成这些数据。具体补齐文件与路由位置见 [Feature Truth](../.claw/truth/features/md-reader-wiki-links-and-graph-boundary.md)。

## 当前边界

- 双链**只渲染与跳转**，不自动补全、不做 `[[` 触发建议。
- 反向链接面板尚未接入界面：索引已在 `backlinks` 里给出数据，但右侧栏目前仍只有标题导航。
- 「未链接提及」（提到标题却没加双链）未实现。
- 文件改名或移动时不会自动改写其它文档里的双链引用。
- 图谱不支持节点拖动固定位置、不支持导出图片、不支持按目录或标签过滤。
- 图谱布局每次进入都重算，不持久化节点坐标。
