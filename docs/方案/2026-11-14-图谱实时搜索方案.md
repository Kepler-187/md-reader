# 图谱实时搜索方案

状态：提案，尚未实现。2026-11-14 用户选择本轮先修交互问题、搜索只出方案。

## 建议的产品形态

在图谱工具栏增加「搜索节点…」输入框及「标题 / 全文」切换，默认标题。不设搜索按钮，输入即更新高亮；清空恢复原观感。较窄窗口时搜索占工具栏下一行，避免把原筛选挤出画面。

| 模式 | 搜什么 | 适合的问题 | 实现位置 |
|---|---|---|---|
| 标题（默认） | 文档 title 和文件名，任一命中即可；不把目录名混进来 | “原型人物在哪”“霓虹有哪些文档” | 前端使用现有 link-index.nodes，无额外扫描或请求 |
| 全文 | 标题 + 正文（包括代码示例），排除 YAML 元数据；显示命中片段 | “哪篇提到医疗贷款”“具体论点写在哪” | 新增服务端检索与正文缓存，不能由图谱逐篇拉文档 |

两种模式使用同一个输入框与相同高亮方式。标题和文件名可能不同，所以默认两者都搜。完整路径显示开关仅影响标签外观，不改变搜索字段；同名文件在结果列表显示目录用于区分。

## 实时交互规则

1. 标题匹配直接用已加载数据，键入后立即更新；中文输入法 composition 结束后更新，避免拼音输入中途闪烁。全文使用约 200–300ms 防抖，并显示正在搜索状态；无需回车提交。
2. 首版用大小写不敏感的字面包含，中文连续词直接匹配，不做正则、拼音、语义扩展或模糊猜测。空白修剪，多词按 AND 匹配并在两种模式保持一致；后续若加入短语引号需另定义规则。
3. 匹配节点增加醒目的外圈并显示名称；非匹配节点适度淡化，已有导航名称继续显示。搜索不是点选，不写 selectedId、不取消固定面板、不重新布局、不随每次输入自动缩放。
4. 搜索命中不表示节点之间有关系，因此不因共同命中而增加边或把无关边高亮。已有选中节点和邻近关系仍保留自己的视觉语义。
5. 输入框旁显示「找到 N 篇，当前图可见 M 篇」。在全项目当前 Profile 范围搜索，但只在当前显示图中高亮。被导航/孤立筛选或局部范围隐藏的命中要说明原因，不能显示成“没搜到”；提供明确的“切到全局”“显示导航/孤立节点”操作，用户点击才改变筛选。
6. 展开轻量结果列表，展示标题、路径，全文多一段命中摘要。点击结果才选中节点并定位/打开信息面板；若目标被筛选隐藏，先明确提示所需显示变化。按 Escape 关闭结果列表，清空按钮清除搜索。不要每键入一个字就把视角移走。

## 技术路径与性能

现有依据：link-index.nodes 有 id/path/title/dir/tags，没有正文；titles 是标题到路径的映射，backlinks.snippet 只是链接标签，不可冒充全文内容。左侧 filterFileTree 只搜文件名和路径，服务端当前没有全文搜索路由。

第一阶段只做标题模式：增加纯匹配函数、查询状态、命中 ID 集合与 Canvas 绘制输入。节点 id 是唯一标识，标签宽度缓存仍只按文本和字体计量。query/matches 不能进入拓扑指纹或仿真 effect；清空搜索时坐标、相机与选中完全不变。几百篇当前库不需要额外 Worker 或搜索引擎。

第二阶段再做全文：新增独立服务端搜索接口，按项目/Profile/contentRoots 隔离。首次按需建立正文检索缓存，此后按路径与 mtime 增量更新；复用扫描与受限读文件能力，不把正文塞进 link-index。正文提取要明确处理 Markdown、代码、YAML，不能把链接索引的“排除代码”逻辑复用成全文“排除代码”。独立 Node 服务的解析依赖需要随 vendor/server 一起打包验证。

请求携带查询、模式和项目/Profile，返回匹配路径、标题、命中字段、摘要及索引版本。前端使用 AbortController 加请求序号，查询改变、切库、切 Profile 或关闭图谱后，旧响应不得覆盖新结果。结果面板可分页，Canvas 的匹配集合必须覆盖全部已检索命中；若因限时/数量限制截断，应返回明确标记，不能把前几十条当作全部结果。

外部文件变动遵循当前显式刷新边界；刷新图谱/关联或应用已知保存、删除、重命名时应失效全文缓存。缓存不能跨内容根暴露文件。搜索失败保留图谱并显示可重试状态，不清空成“零结果”。

## 分阶段验收

- 标题阶段：中文输入、大小写、标题与文件名不同、同名跨目录、多词、清空、零命中；导航与孤立/局部隐藏结果说明；高亮不改变拓扑、相机、选中与拖拽。
- 全文阶段：仅正文命中、代码命中、YAML 不命中、标题命中；新增/修改/删除的失效；快速输入乱序、切项目/Profile、不支持文件和越界路径；部分结果/错误可辨认。
- 性能目标须实测：标题输入在当前库不造成可感知卡顿；全文首次索引单独计时，缓存后交互延迟与最大库规模一起报告，不先承诺未经验证的毫秒数。

建议先交付标题模式验证交互，再补全文。全文的工作量主要是正文索引和失效，而不是多加一个切换按钮。本轮没有加入任一模式的搜索代码。
