# 扩展与内容兼容边界

## 内容优先级

扩展功能必须服从 Markdown-first 原则：首先保证源文件不丢失、不越界写入、可在其他 Markdown 工具中继续使用；其次才考虑更丰富的界面效果。

## 适合可视编辑的内容

标题、段落、列表、引用、强调、链接等常见 Markdown 结构适合作为可视编辑的主要范围。新增可视编辑能力时，应同时验证：

- 保存后仍得到正确的原生 Markdown。
- 切换到分栏左侧时能看到可理解的真实源码。
- 最终预览与可视编辑没有语义性分歧。

## 需要保真或精确编辑的内容

复杂表格、frontmatter、原始 HTML、特殊 fenced code block、复杂嵌入及尚未稳定支持的结构，不应被应用为了“看起来更可视”而自动重写。应保留为源码片段，或明确引导用户使用分栏左侧编辑。

## 图片资源与 YAML front-matter

只读预览（含分栏右侧）通过 `remark-frontmatter` 识别并隐藏开头的 YAML 元数据；文件内容、分栏左侧源码和保存内容不被裁剪。正文分隔线与代码块中的 YAML 仍正常显示。

本地 Markdown 图片按当前文章目录解析 `../` 和百分号编码，复用文档链接的路径规范化与 `contentRoots` 检查。目标必须位于允许的内容根内；越界、绝对路径或不支持的协议显示带诊断属性的 alt 文本，不生成错误的图片 URL。图片可以跨同一项目内的允许内容根引用，不要求出现在只包含 Markdown 的文件树中。

前端通过注入的 `getAssetHref` 生成 `GET /api/projects/:projectId/asset?profileId=...&path=...`；接口也支持 HEAD。服务端拒绝绝对路径、父目录跳转、Windows 盘符/反斜线/备用数据流，检查符号链接与 junction 的真实路径不能越出项目和内容根，仅提供 PNG/JPEG/GIF/WebP/SVG/BMP/AVIF/ICO。响应带 MIME、长度、最后修改时间和 `private, max-age=300` 缓存头；SVG 同时受 sandbox CSP 和 nosniff 约束。未知资源返回 404，不支持的类型返回 415，越界返回 400/403。

`http://`、`https://`、`data:` 图片原地址保留，不经过本地接口；外链可用性取决于远端。预览图片使用浏览器懒加载、异步解码并限制到阅读区宽度，保持宽高比。没有额外的远端图片代理、失败重试、缩略图生成或上传功能；同路径替换图片可能最多等待五分钟缓存过期。

## Mermaid 扩展规则

Mermaid 只属于最终预览层。增加图表交互时不得改变源码、不得让图表状态进入 Markdown 或 Profile，也不能让单张图的渲染失败影响整篇文档。

## sidecar 元数据

项目的长期方向允许把高价值、非正文语义的展示状态放入与 Markdown 同名的 `*.md.meta.json` sidecar，例如页面宽度、表格列宽、callout 类型或图片展示模式。

这不是当前正式用户工作流的既有能力。任何 sidecar 落地前都必须先明确其数据合同、文件生命周期、与 Markdown 的一致性和降级策略；标题导航、当前模式、文件树展开等个人状态不应迁入 sidecar。

## 新服务能力的约束

新增项目或文件 API 时必须保持：

- 仅监听本机回环地址，除非安全模型被重新设计。
- 所有路径经过相对路径与内容根校验。
- 写入具有明确的冲突保护，不静默覆盖外部改动。
- API、测试与本文档同步更新。
